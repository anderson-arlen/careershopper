# Profile onboarding

1. Read `resume_content_get`, `profile_get`, and existing searches first.
2. Ask about contact information, employment and dates, accomplishments,
   technologies, projects, education, and then job preferences.
3. Add user-approved wording to Resume content. Preserve date precision and
   existing titles, IDs, dependencies, ordering, and enabled settings.
4. Store useful work history that should not appear in applications as disabled
   entries. It remains available for matching. Pending imported employment uses
   `verification_status: "pending"` and stays disabled until reviewed.
5. Save through `resume_content_save` with the current revision and explicit
   authorization. Do not create a parallel career-facts collection.
6. Save preferences separately. A desired skill is not evidence of experience.
7. Read sources and searches before making requested search-strategy changes.
8. Summarize additions and any unresolved dates or factual uncertainties.

Use the full saved content for matching and only enabled content for application
materials. Never disclose disabled entries just because they informed a match.
